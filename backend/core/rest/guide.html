TRELLIS · STAFF DEVELOPER API

Course data and authoring API

Download OpenAPI 3.1 specification · Base path: /api/v1/

Create a token in Course settings → API access. Tokens belong to one course and retain only their owner's current staff permissions. Never put tokens in source control or browser URLs.

Quick start

export TRELLIS_URL="https://your-trellis-host"
# Set TRELLIS_API_TOKEN securely in your terminal environment.
curl -H "Authorization: Bearer $TRELLIS_API_TOKEN" \
  "$TRELLIS_URL/api/v1/courses/"

Core conventions

  • Assignment ID is a stable section/lesson ID; part ID is a stable activity ID. Revision IDs change when content or files change.
  • JSON responses are paginated with results, count, next, previous, limit, offset. Follow the relative next URL; maximum page size is 200.
  • Use If-Match: "REVISION_ID" or base_revision_id for part writes. A stale draft returns 412; missing precondition returns 428.
  • Content, grading and file edits create drafts. Titles, ordering and metadata apply immediately. Publish drafts explicitly using the publish endpoint and a token with content:publish.
  • New file uploads require explicit visibility: student, staff, or grader. Grader/solution paths cannot be made student-visible. File data is UTF-8 text or base64, up to 1 MB.
  • Use an Idempotency-Key for retryable writes. The same token/key/request replays the original response; changing the body with that key returns 409.
  • Times are UTC ISO 8601. Coding submission time is its actual queue receipt time, not when grading finished. Historical first-open times that were not tracked remain null.
  • Dropping an enrollment or deleting course content preserves work and submission history.
  • Content-read tokens can read private staff/grader files and answer keys. Give scripts only the scopes they need. Roster writes and API audit access require an instructor.

Updating a coding part

# Fetch current draft and its revision ID.
curl -H "Authorization: Bearer $TRELLIS_API_TOKEN" \
  "$TRELLIS_URL/api/v1/parts/PART_ID/"

# file-update.json: {"visibility":"student", "text":"print(123)\n"}
curl -X PUT -H "Authorization: Bearer $TRELLIS_API_TOKEN" \
  -H 'Content-Type: application/json' -H 'If-Match: "REVISION_ID"' \
  --data-binary @file-update.json \
  "$TRELLIS_URL/api/v1/parts/PART_ID/files/main.py"

# Publish the NEW revision ID returned by the write.
curl -X POST -H "Authorization: Bearer $TRELLIS_API_TOKEN" \
  -H 'Content-Type: application/json' -H 'If-Match: "NEW_REVISION_ID"' \
  --data '{}' "$TRELLIS_URL/api/v1/parts/PART_ID/publish/"

Grading definitions

Use the missing-grader report to find exercises that need tests. Upload a JSON definition with PUT /parts/{id}/grader/, test it through the local isolated runner, then publish. Student code never executes in the web server.

Rename part titles

Use PATCH /api/v1/courses/{course_id}/parts/titles/ with a content:write token. Supply up to 500 unique IDs and their current titles. A conflict rejects the whole batch. Titles change immediately; content revisions, files, and student records stay intact.

{"updates":[{"id":123,"expected_title":"Old title","title":"Updated title"}]}

The course structure editor also supports editable titles, Save changes, Undo, and Discard changes. Outline changes remain local drafts until saved together. Undo applies before Save.

Errors

{"error":{"code":"revision_conflict","message":"This part changed..."},"request_id":"..."}

Use the returned request ID to correlate failures. Audit records contain resource IDs and actions, not passwords, API secrets, or full request bodies.
